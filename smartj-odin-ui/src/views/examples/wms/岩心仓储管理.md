# 岩心仓库3D可视化管理系统 — 技术方案

---

## 一、项目概览

基于实际岩心仓库照片（奥特莱物流科技自动化立体仓库），构建一个 **Babylon.js 3D 可视化仓储管理演示系统**，实现仓库、货架、托盘、岩心盒子的参数化建模与入库/出库动画模拟。

**技术栈**：Vue 3 + Element Plus + Tailwind CSS + Babylon.js

## 三、核心数据模型设计

### 3.1 仓库配置（WarehouseConfig）

```typescript
interface WarehouseConfig {
  // 仓库整体尺寸
  width: number;       // 仓库宽度 (m)，默认30
  length: number;      // 仓库长度 (m)，默认60
  height: number;      // 仓库高度 (m)，默认15

  // 货架排布
  aisleWidth: number;      // 通道宽度 (m)，默认3.5
  rackDepth: number;       // 货架深度（单排，m），默认1.2
  rackRows: number;        // 货架排数（横向），默认12
  rackColumns: number;     // 货架列数（纵向），默认4

  // 货架结构参数
  rackLevels: number;      // 货架层数，可配置，默认8层
  levelHeight: number;     // 每层净高 (m)，默认1.2
  beamThickness: number;   // 横梁厚度 (m)，默认0.12
  uprightWidth: number;    // 立柱宽度 (m)，默认0.1

  // 颜色方案（参考实物照片）
  colors: {
    upright: string;       // 立柱颜色，默认 '#1a5ab8'（蓝色）
    beam: string;          // 横梁颜色，默认 '#d4412a'（红橙色）
    floor: string;         // 地面颜色
    wall: string;          // 墙壁/背景色
  };
}
```

### 4.2 参数化建模 — 模型工厂（ModelFactory）

核心思路：**所有3D几何体均由配置参数驱动生成，不硬编码尺寸。**

#### 4.2.1 立柱与横梁

```typescript
class RackBuilder {
  static build(config: RackConfig, warehouseCfg: WarehouseConfig): Mesh[] {
    const meshes: Mesh[] = [];
    const { levelHeight, levels, beamThickness, uprightWidth } = warehouseCfg;
    const totalHeight = levels * levelHeight;

    // 立柱：使用BoxGeometry，根据参数动态创建
    // 左立柱 + 右立柱
    const upright1 = MeshBuilder.CreateBox('upright', {
      width: uprightWidth,
      height: totalHeight,
      depth: warehouseCfg.rackDepth
    });
    const upright2 = upright1.clone('upright2');
    // 位置根据 rackPosition + 偏移计算

    // 横梁：每层两根（前横梁 + 后横梁）
    for (let level = 0; level < levels; level++) {
      const beamY = level * levelHeight + beamThickness / 2;
      const frontBeam = MeshBuilder.CreateBox('beam_front_' + level, {
        width: config.palletWidth * config.columns + uprightWidth * 2,
        height: beamThickness,
        depth: uprightWidth
      });
      // ... 类似创建后横梁、斜撑
    }
    return meshes;
  }
}
```

#### 4.2.2 岩心盒堆叠

```typescript
class CoreBoxBuilder {
  static buildStack(
    boxSpec: CoreBoxSpec,
    count: number,
    palletConfig: PalletConfig
  ): TransformNode {
    const parent = new TransformNode('boxStack');

    for (let i = 0; i < count; i++) {
      const box = MeshBuilder.CreateBox('coreBox_' + i, {
        width: boxSpec.width / 100,   // cm → m
        height: boxSpec.height / 100,
        depth: boxSpec.depth / 100
      });
      box.position.y = (palletConfig.height / 100) + i * (boxSpec.height / 100);
      box.parent = parent;

      // 材质：根据规格赋不同颜色
      // 可贴标签纹理模拟实物
    }
    return parent;
  }
}
```

#### 4.2.3 叉车模型

叉车为简化低多边形模型（可手动建模或使用基础几何体拼装）：

```
Forklift 组成：
├── 车体 (Box) — 带驾驶室轮廓
├── 底盘 + 4个车轮 (Cylinder)
├── 门架 (2根竖直Cylinder + 横向连接) — 可上下滑动
├── 货叉 (2个薄Box) — 可伸缩
└── 配重 (Box) — 车尾
```

门架与货叉绑定骨骼或使用父子TransformNode实现升降动画。

## 五、场景参数化与动态重建

### 5.1 配置驱动的重建流程

```
用户修改参数 → configStore更新 → 触发watcher
    → scene.clear() 清除旧模型
    → WarehouseBuilder.build(newConfig) 重新生成
    → 恢复库存状态到模型上
    → scene.render()
```

### 5.2 WarehouseBuilder 核心逻辑

```typescript
class WarehouseBuilder {
  build(config: WarehouseConfig): void {
    // 1. 构建地面和墙壁
    this.buildFloor(config.width, config.length);
    this.buildWalls(config);

    // 2. 计算货架布局
    const rackSpacing = config.aisleWidth + config.rackDepth;
    for (let row = 0; row < config.rackRows; row++) {
      for (let col = 0; col < config.rackColumns; col++) {
        const position = this.calcRackPosition(row, col, config);
        const rackConfig = this.getRackConfig(row, col, config);
        const rack = new RackBuilder(rackConfig, config);
        rack.buildAt(position);
      }
    }

    // 3. 放置叉车
    this.placeForklift(config);
  }
}
```

## 六、入库/出库动画系统

### 6.1 动画流程设计

#### 入库（Put-away）

```
1. 用户指定待入库的岩心盒信息（规格、数量）
2. 系统自动分配货架位置（或用户指定）
3. 叉车从入库通道起点出发
4. 叉车驶向待入库托盘 → 停下 → 门架下降 → 货叉插入托盘 → 门架上升（装载）
5. 叉车沿通道行驶至目标货架前方
6. 门架升至目标层高 → 货叉前伸 → 门架微降（放置）→ 货叉收回
7. 叉车门架降至行驶高度 → 返回通道起点
8. 更新库存状态
```

#### 出库（Pick）

```
1. 用户指定出库目标（货架位置/岩心盒编号）
2. 叉车从通道起点出发
3. 叉车驶至目标货架前方
4. 门架升至目标层高 → 货叉前伸 → 门架微升（拾取）→ 货叉收回
5. 门架降至行驶高度
6. 叉车驶回出库通道指定位置 → 停下 → 门架下降 → 放置 → 货叉收回
7. 更新库存状态
```

### 6.2 动画技术实现

使用 **Babylon.js Animation 系统 + 动作队列（ActionQueue）**：

```typescript
interface AnimationStep {
  type: 'move' | 'lift' | 'extend_forks' | 'lower_forks' | 'wait';
  target?: Vector3;       // 移动目标位置
  duration: number;       // 动画时长 (ms)
  easing?: EasingFunction;
}

class ForkliftAnimator {
  private queue: AnimationStep[] = [];
  private scene: Scene;

  enqueuePutAway(boxStack: TransformNode, targetSlot: PalletSlot): void {
    // 计算路径点并入队
    const forkliftStart = new Vector3(/* 入库口 */);
    const palletPickup = this.getPalletWorldPosition(boxStack);
    const rackApproach = this.getRackApproachPosition(targetSlot);
    const rackPlace = this.getRackSlotPosition(targetSlot);

    this.queue = [
      { type: 'move', target: palletPickup, duration: 2000, easing: CubicEase },
      { type: 'lower_forks', duration: 800 },
      { type: 'lift', target: /* 托盘高度 */, duration: 1000 },  // 装载
      { type: 'move', target: rackApproach, duration: 3000, easing: CubicEase },
      { type: 'lift', target: rackPlace.y, duration: 1500 },     // 升至目标层
      { type: 'extend_forks', duration: 600 },                   // 放入
      { type: 'lower_forks', duration: 400 },                    // 放下
      { type: 'extend_forks', duration: 600 },                   // 收回
      { type: 'lift', target: /* 行驶高度 */, duration: 800 },
      { type: 'move', target: forkliftStart, duration: 2500 },
    ];
  }

  async play(): Promise<void> {
    for (const step of this.queue) {
      await this.executeStep(step);
    }
    this.queue = [];
  }
}
```

### 6.3 路径规划（简化版）

由于仓库为规则矩形布局，路径采用简化规则：

- **横向移动（沿通道）**：沿Y轴平移
- **纵向移动（通道间）**：沿X轴移动到目标通道
- **避障**：固定路线，不经过其他货架位置
- 可后续扩展为A*寻路（如需更真实的路径规划）

```
俯视路径示意：
                    入库口
                      │
     ═══════════════════════════  ← 主通道
     ║ A1 ║ 通道 ║ A2 ║ 通道 ║ A3 ║ ...
     ═══════════════════════════
              ↑     ↑
           目标位  叉车路径
```

## 八、性能优化策略

| 问题 | 方案 |
|------|------|
| 货架数量多，几何体多 | 使用 **实例化渲染（InstancedMesh）**：相同规格的立柱、横梁、盒子只创建一个原型Mesh，其余用Instance复用 |
| 每帧重绘开销 | 静态物体冻结世界矩阵 `mesh.freezeWorldMatrix()` |
| 入库/出库动画卡顿 | 使用 `scene.beginAnimation()` 而非手动setPosition，让引擎调度 |
| 大场景加载慢 | 分区构建：先渲染相机可视区域，其余延迟加载 |
| 标签/文字 | 使用 **动态纹理（DynamicTexture）** 在Plane上绘制文字标签，避免TextMesh开销 |

```
    │  更新库存数据            │
```

关键：Babylon.js 场景封装在 `BabylonScene.vue` 组件中，通过 `defineExpose` 或事件总线暴露控制接口，避免Vue响应式系统与引擎内部状态冲突。

## 十一、技术风险与注意事项

1. **Babylon.js 与 Vue 3 生命周期**：组件卸载时必须调用 `engine.dispose()` 和 `scene.dispose()` 释放GPU资源，避免内存泄漏。
2. **大规模实例化**：若仓库配置较大（如20排×4列×8层×2列 = 1280个托盘位），需合理使用 InstancedMesh，预估几何体数量并设置合理上限。
3. **动画中断**：用户在动画执行中修改配置时，需要先取消当前动画（`scene.stopAllAnimations()`），再重建场景。
4. **坐标系**：Babylon.js 使用左手坐标系（Y向上），建模时所有尺寸统一为米（m），内部使用 cm 输入但转换为 m 后参与建模。
5. **响应式性能**：配置面板的滑块拖动会频繁触发重建，需做 **防抖处理（debounce 300ms）**，避免每帧重建。
